# 일상·경량 작업 (토큰 절약)

> 목적: **작은 요청에 큰 절차를 쓰지 않는다.** 안전 규칙(AGENT.md·훅)은 그대로 두고
> 과정만 가볍게 한다.

## 판단 기준 — 이 모드로 처리해도 되는가
다음 전부에 해당하면 경량 모드로 진행한다:
- 바꿀 파일을 이미 알거나, 한 번의 검색으로 특정된다
- 설계 결정이 없다 (동작 방식을 고르는 일이 아니라 고치는 일)
- diff 가 대략 20줄 이내다

하나라도 아니면 `development` 스킬(Read → Think → Plan → Edit → Verify)로 전환한다.
**전환 판단을 스스로 알린다** — "범위가 커져서 일반 절차로 진행합니다" 한 줄이면 된다.

## 경량 모드 규칙
- **읽기 최소화**: 대상 파일(과 직접 참조되는 것)만 연다. 주변 파일 사전 탐색 금지.
- **계획 문서 생략**: `PLAN.md` 를 만들지도 갱신하지도 않는다. 단계가 생기는 순간 경량 모드가 아니다.
- **끼워넣기 금지**: 눈에 띈 리팩터링·정리는 하지 않는다. `.docs/plans/tech-debt.md` 에 한 줄 적고 넘어간다.
- **보고는 3문장 이내**: 무엇을 바꿨고, 어떻게 확인했는지. 배경 설명·대안 나열 생략.
- **검증은 생략하지 않는다**: `.scripts/verify.sh` 통과는 경량 모드에서도 "완료"의 정의다.
  (훅이 어차피 강제한다 — 건너뛰려 하지 말 것.)

## 예시
| 요청 | 처리 |
|---|---|
| "타임아웃 5초로 늘려줘" | 해당 상수 위치 특정 → 수정 → verify → 한 줄 보고 |
| "이 에러 뭐야?" | 스택의 해당 파일만 읽고 원인 설명 (수정 요청 전엔 고치지 않음) |
| "README 오타 고쳐줘" | 수정 → verify → 완료 |
| "로그인 흐름 바꿔줘" | 경량 아님 → development 로 전환한다고 알리고 진행 |
