# 문서 작성

> 기본 언어 **{{FILL:docs.language}}** · 톤 **{{FILL:docs.tone}}** · 주 포맷 **{{FILL:docs.primary_format}}**

## 시작 전
- **요청하지 않은 문서를 자발적으로 만들지 않는다.** README·요약 .md 를 임의로 생성하지 않는다.
- 새로 만들기보다 기존 문서 수정을 먼저 고려한다.
- 독자를 특정한다(입문자 / 동료 엔지니어 / 의사결정자). 깊이와 용어가 달라진다.

## 구조
- **결론 먼저.** 무엇을·왜를 첫 단락에 둔다. 배경을 앞세우지 않는다.
- 한 문서 = 한 목적. 목적이 둘이면 나눈다.
- 스캔 가능하게: 절차는 번호목록, 병렬 항목은 불릿, 비교는 표. 연결된 논리는 문장으로 쓴다(목록 남발 금지).

## 표기
- 파일 경로·함수명·명령어·식별자는 인라인 코드로 감싼다. 코드블록에는 언어를 명시한다.
- 명령어 예시는 **실제 동작하는** 형태로. 플레이스홀더는 `${VAR}` / `<your-token>` 처럼 분명하게.
- 대시는 ASCII 하이픈(`-`). 특수 유니코드 대시는 렌더링이 깨진다.
- 상대 날짜("어제") 대신 절대 날짜(`2026-05-27`).
- 이모지는 사용자가 명시 요청할 때만.

## 인용에서 반드시 지킬 것
- 외부 사실에는 출처 URL 을 단다 → `.skills/web-research/SKILL.md` 의 인용 규칙.
- **도구 내부 토큰을 본문에 남기지 않는다**: `[145036†L1-L9]`, `【turn1†view0】` 같은 것.
  사람이 읽는 표준 인용으로 바꾼다.
- 깨진 URL·`TODO 작성` 같은 플레이스홀더를 최종본에 남기지 않는다.

## 문서 유형별
| 유형 | 첫 줄에 둘 것 | 흔한 실수 |
|---|---|---|
| README | 이게 무엇이고 어떻게 실행하는지 | 설치법 누락, 장황한 철학 |
| 설계 문서 | 결정과 이유, 고려한 대안 | 구현 디테일만 나열 |
| PR 본문 | 무엇을·왜 바꿨는지 + 테스트 방법 | diff 를 그대로 설명 |
| 변경 요약 | 사용자에게 미치는 영향 | 내부 리팩터링 자랑 |
