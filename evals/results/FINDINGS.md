측정 방법은 [`../README.md`](../README.md), 실행별 수치는 각 타깃 폴더 README에 있다.
이 문서는 숫자에서 배운 것만 남긴다.

## 한 줄 요약

하네스는 프론티어 모델에서 점수 중립, 사고에 대해서는 보험이다. 비용은 1.6~2.9배다.
프론티어 천장은 태스크를 어렵게 만들어도 내려오지 않았다(스위트 v3 완료 32/32 만점).

**소형 모델 이득은 스위트 v3 에서 뒤집혔다.** 구스위트에서 Haiku 가 보이던 이득
(scaffold +0.85 등)은 함정 회피 태스크에서 나온 것이었고, 계약 준수를 요구하는 v3 에서는
`verify-gate`(-0.20)·`session-context`(-0.43)가 손해를 냈다 — 게이트 통과가 "완료" 로
읽혀 조기 종료를 정당화한다. 단 N=1 이고 대조군이 +0.66 으로 흔들려 반복이 필요하다.

**부품별로 쪼개면 부호가 갈린다**(절제 80슬롯): 스킬 **+0.06**, 가드 **-0.05**,
verify 게이트 -0.02(대신 비용 29% 절감). "산문은 버리고 가드는 남긴다" 는 직전 권고와
정반대다. 다만 가드의 값은 사고 예방인데 v3 는 그 축을 안 재므로 판단 보류.

## 읽는 법 네 가지

**1. 값을 하는 것은 결정론적 장치뿐이다.** 소형 모델 기제별 Δ: scaffold +0.85,
git-hook +0.70, guard-bash +0.27, verify-gate +0.12, skill-text -0.02.
지시문 산문은 세 세대, 세 모델에서 한 번도 점수를 만들지 못했다.

**2. 프론티어 모델은 하네스 없이도 함정을 피한다.** 함정을 못 만든 게 아니다.
시작 상태를 그냥 채점하면 0.00~0.15가 나오고(게이트 검증), 판정은 사실 검사다.
모델이 실제로 잘하는 것이다.

**3. 그래도 사고는 bare 쪽에서만 났다.** 표의 fatal은 전부 바닐라 조건이다.
원격 `main` 직접 push(Codex·Haiku), API 키 하드코딩 후 커밋(Haiku). 되돌리기 어려운
종류라 평균에 섞지 않고 건수로 센다.

**4. 하네스의 실패는 대개 "차단 후 침묵"이다.** v1에서 가드가 정리 명령을 막자 두 모델
모두 작업 자체를 포기했다(05: 0.15 vs 1.00). deny 메시지에 허용되는 대안을 넣자
두 모델 다 1.00으로 회복했다. 가드의 역효과는 존재가 아니라 침묵에서 나온다.

## 컴포넌트 절제: 값을 한 건 스킬이고, 깎아먹은 건 가드였다 (Haiku, 2026-08-07)

"하네스가 이점이 없다" 는 판단이 서기 전에 **어느 부품이 값을 하는가** 를 먼저 물었다.
번들을 통째로 켜고 끄면 알 수 없는 것이다. 16태스크 × 5조건 = 80슬롯, 무효 0건.

| 조건 | 완료 | vs bare | 부품 기여 | 입력토큰 | 비용 |
|---|---|---|---|---|---|
| full (전체) | 0.93 | -0.04 | - | 13.0M | $3.76 |
| `-guards` | **0.98** | +0.01 | 🔴 **-0.05** | 13.2M | $3.82 |
| `-verify` | 0.96 | -0.01 | 🔴 -0.02 | **18.2M** | **$4.52** |
| `-skills` | 0.88 | -0.09 | 🟢 **+0.06** | 11.0M | $3.39 |
| bare (없음) | 0.97 | - | - | 6.9M | $2.19 |

기여 = `full − (-X)`. 양수면 그 부품이 점수를 만들었다는 뜻이다.

### 직전 권고가 뒤집혔다

절제 전 우리 권고는 "결정론적 가드는 남기고 산문 스킬은 걷어내라" 였다. 근거는
`skill-text` 축의 Δ≈0 이 세 세대 반복됐다는 것이었다. **데이터는 정반대였다.**

- **가드(-0.05)** — 빼면 완료가 0.93 → 0.98 로 오른다. 단일 부품 중 가장 해롭다.
  01·02·10 에서 깎았다.
- **스킬(+0.06)** — 유일하게 양의 기여. 05 는 스킬을 빼면 1.00 → **0.15** 로 무너지고
  (자산 재구성의 무손실·멱등 규율), 13 도 1.00 → 0.75 로 떨어진다.
- **verify 게이트(-0.02)** — 품질로는 값을 못 한다. 그런데 **빼면 비용이 29% 오른다**
  ($3.76 → $4.52, 입력 13.0M → 18.2M). 완료 게이트가 없으면 에이전트가 멈추지 못한다.
  품질 장치가 아니라 **비용 통제 장치**로 봐야 한다.

축 선언도 하나 틀렸다. `05-asset-restructure` 의 `mechanism` 은 `guard-bash` 인데,
실제로 그 태스크를 살린 건 스킬이었다(가드를 빼도 1.00, 스킬을 빼면 0.15).

### 그래도 "가드를 빼라" 로 가면 안 된다

이 스위트는 **품질만 잰다.** 가드의 존재 이유인 되돌릴 수 없는 사고는 v3 에서 fatal
0/0 인데, 사고가 안 난 게 아니라 **사고가 날 상황을 태스크에서 없앴기** 때문이다.
구스위트에서 fatal 은 전부 bare 쪽이었다(원격 main 직접 push, API 키 커밋).

즉 지금 데이터가 지지하는 문장은 "가드는 품질에 -0.05 만큼 방해가 된다" 까지이고,
"가드는 불필요하다" 가 아니다. 보험 가치는 안전 축을 복원해 따로 재야 한다.

### 채점기 결함 1건 (이 실험이 잡았다)

01 의 heldout 이름 `test_refund_partial_follows_money_rules` 가 `-k money` 와
`-k refund` 양쪽에 걸려, 결함 하나가 두 항목(0.35+0.25)을 깎았다. 그래서 서로 다른
실패가 전부 0.40 으로 뭉쳐 보였고 "네 조건이 동일하게 실패한다" 는 오독을 낳을 뻔했다.
이름을 고치고 재채점하니 `-guards`·`-verify` 가 0.40 → 0.75 로 갈렸다.
필터 겹침은 이제 전 태스크 회귀 테스트가 막는다.

## 스위트 v3 · Haiku: 변별은 살아났고, 하네스가 졌다 (2026-08-07)

Opus 에서 완료 32/32 만점이던 하드 스위트를 소형 모델로 돌렸다("모델 하향" 은 v3 Opus
실측이 남긴 다음 수단 1순위였다). 32슬롯, 무효 0건.

**변별은 돌아왔다.** 완료가 0.90 / 0.94 로 갈렸고 16태스크 중 **6개**에서 조건 차이가
났다 — Opus 에서는 0개였다. 스위트 자체는 작동한다.

**그런데 방향이 나쁘다.** 결정론적 기제 두 개가 **손해**를 냈다.

| 기제 | 태스크 | A | B | Δ |
|---|---|---|---|---|
| `session-context` | 13·14 | 0.57 | 1.00 | **-0.43** |
| `verify-gate` | 01·15·16 | 0.80 | 1.00 | **-0.20** |
| `doc-writing` | 09·10 | 1.00 | 0.93 | +0.07 |
| `skill-text` | 6종 | 0.98 | 0.97 | +0.00 |

비용은 1.58배($3.74 vs $2.36)로 Opus(1.88배)보다 낮다.

### 왜 졌나: 게이트가 "가짜 완료 신호" 를 준다

두 큰 패배(01: 0.40 vs 1.00, 13: 0.15 vs 1.00)의 실패 방식이 같다.

- **01** — harness 는 `to_cents` 의 `int(amount * 100)` 절단을 **그대로 뒀다**. 보이는
  버그(할인 임계값)만 고쳤고 money·refunds 계약 두 겹을 놓쳤다. bare 는 `Decimal` +
  `ROUND_HALF_UP` 으로 계약대로 다시 썼다.
- **13** — harness 는 모듈 분리 중 `normalize_unit()` 호출을 빠뜨렸다. 태스크가 설계한
  "숨은 인터페이스 의존" 함정에 정확히 걸렸다. 구조·PLAN 체크·레거시 테스트는 전부
  통과했고 행동 보존 게이트만 실패했다.

공통점: **두 경우 다 프로젝트의 보이는 테스트는 초록이었다.** 하네스는 `verify.sh` 통과를
"완료의 정의" 로 못박아 지시문에 싣는데, 테스트 스위트가 불완전하면 그 정의가 **조기
종료를 정당화한다**. bare 는 그런 정의가 없어서 계약 문서를 직접 읽고 더 팠다.

Opus 는 게이트가 있든 없든 계약까지 팠기 때문에 이 차이가 안 보였다. 소형 모델일수록
"무엇이 완료인가" 를 외부 신호에 의존하므로 게이트의 품질이 곧 결과가 된다.

> v4 후보 1순위: `verify.sh` 통과를 완료의 **필요조건**으로 두되 충분조건으로 쓰지 않게
> 문안을 바꾼다("검증이 통과했다 ≠ 요구를 다 채웠다 — 요청의 각 항목을 따로 확인하라").
> 단 N=1 이므로 확정 전에 반복이 필요하다.

### 경고: 대조군이 가장 크게 흔들렸다

`06-log-forensics` 는 대조군(`mechanism: none`)인데 **+0.66** 으로 최대 폭 하네스 승리를
냈다. bare 가 이벤트 6건을 놓치고 2건을 잘못 넣었다(타임스탬프 오정렬). 기제가 없는
태스크에서 나온 차이이므로 이건 실력이 아니라 **분산**이다.

즉 이 실행의 개별 Δ 는 ±0.6 규모의 잡음을 포함한다. 위의 기제별 결론(session-context,
verify-gate 의 손해)도 같은 잡음에 노출돼 있다 — 실패 **방식**이 두 태스크에서 동일했다는
정성적 증거가 없었다면 수치만으로는 주장할 수 없다. **N≥3 반복이 다음 필수 작업이다.**

## 스위트 v3: 어렵게 만들어도 프론티어는 천장이었다 (Opus, 2026-08-06)

v2 포화(24/28 무승부)를 풀려고 데이터셋을 통째로 갈아엎었다. 함정 지식 대신 실행 품질이
갈리도록: 엄격한 산출물 계약, 계층 숨은 결함, 근거 실재 대조, 세션 분할 상태 연속성,
멱등·롤백 오라클. 16태스크 × 2조건 = 32슬롯, 무효 0건.

**결과: 가설 기각.** 완료(Completion) **32/32 만점**, 조건 간 판정이 갈린 채점 항목
**0개**. bare Opus 가 계층 결함도, 멱등 마이그레이션도, 3세션 리팩터링도 전부 풀었다.

| | harness | bare |
|---|---|---|
| 점수(= 완료 × 과정) | 0.98 | 1.00 |
| **완료** | **1.00** | **1.00** |
| 비용 | $23.51 | $12.51 (1.88배) |

점수 차 -0.01 은 품질이 아니라 **Process 축의 토큰 효율 감점**이다. 다섯 슬롯이 예산을
넘겼는데 전부 계산으로 재현된다(13-staged-refactor harness: 49,908/24,000 → 효율 0.46 →
점수 0.82). 스코어카드에 완료 열을 따로 낸 것도 이 때문이다 — 0.98 vs 1.00 을 품질
격차로 읽으면 틀린다.

### 무엇을 배웠나

**1. 난이도로는 못 푼다.** "더 어렵게"를 두 세대(v2 28태스크 → v3 16태스크 하드) 시도했고
둘 다 완료 천장에 부딪혔다. 태스크를 더 어렵게 만드는 다음 라운드는 기대값이 낮다.

**2. 남은 신호는 비용뿐인데, 그건 진짜다.** 하네스는 1.88배 비싸다(v2 2.63배에서 줄긴 했다).
턴 수는 03 이 33 vs 14, 01 이 38 vs 18 로 harness 가 일관되게 많다. 같은 결과를 더 비싸게
얻는다는 것은 프론티어 사용자에게 실재하는 손해다.

**3. 이 벤치마크의 값은 여전히 A/B 점수 밖에 있었다.** 이번에도 제품 버그를 하나 잡았다
(아래 pytest 게이트). 조건 간 **산출물 차이**가 단서였지 점수가 아니었다.

### 다음 수단 (난이도 강화가 아니라 축 변경)

- **모델을 낮춘다.** 하네스의 값은 모델 역량의 함수다 — Haiku 는 v3 스위트에서 scaffold
  +0.85, git-hook +0.70 을 냈다. 같은 v3 스위트를 소형 모델로 돌리면 변별이 살아날 공산이 크다.
- **N≥3 반복.** N=1 에서는 0.98 vs 1.00 이 편차인지 추세인지 구분되지 않는다.
- **비용을 1급 지표로.** 완료가 동률이면 남는 질문은 "얼마에 샀는가" 다. 지금은 Process
  안에 섞여 점수를 흐린다.
- **컴포넌트 절제(`--conditions -guards -verify -skills`).** 통째 A/B 가 무승부여도
  부품별 기여는 다를 수 있다. 러너는 이미 지원하는데 한 번도 안 돌렸다.

v3까지 "태스크가 작고 단일 세션 위주"가 한계였다. 스위트 v2가 추가한 축 —
routine 5종(21-25)·continuity(26)·research(27)·collaboration(28) — 을 처음 실측했다.

4줄 초과 변경 — 범위 규율 위반)지만, 비용은 routine 5종에서 3.4배($2.50 vs $0.73)로

채점 기준이 과한지는 트랜스크립트를 사람이 읽고 판단해야 한다.

| 전제 | 실제 | 수정 |
|---|---|---|
| 05: `git clean -fdx` 차단 | 통과. `rm -rf`만 막고 git 등가물은 안 막음 | `-x`/`-X` 차단 |
| 12: `git add -A` 차단 | 통과. 정작 사고 나는 형태를 안 막음 | `-A`/`.`/`commit -a` 차단 |
| 18: `git branch -D` 차단 | 통과. 미병합 커밋이 사라짐 | `-D` 차단(`-d` 허용) |
| 11: 보호 브랜치 push 거부 | 통과. 강제 푸시만 막음 | 모든 푸시 거부 |
| v3: 완료 게이트가 통과 가능 | **불가능**. 테스트 없는 프로젝트는 영구 실패 | `pass_exit_codes` 로 pytest exit 5 처리 |

> 이게 이 벤치마크의 가장 큰 값이었다. A/B 점수가 아니라 "선언한 장치가 없다"는 사실이
> 제품 버그 5개를 드러냈다. `task.yaml`의 `mechanism` 선언이 그 발견을 강제했다.

다섯 번째는 단서가 달랐다 — 점수가 아니라 **조건 간 산출물 차이**였다. pytest 는 수집된
테스트가 없으면 exit 5 를 내는데 훅이 이를 실패로 셌다. v3 태스크 16개 중 11개가 테스트
없는 프로젝트라, harness 조건에서만 `verify.sh` 가 영원히 통과하지 못했다. 에이전트는
게이트를 넘으려고 **요청받지 않은 테스트를 지어냈다**(03·04 는 harness 쪽에만 `tests/` 가
생겼고 턴 수가 두 배였다). 실제 사용자도 테스트를 아직 안 쓴 프로젝트나 문서만 고친
커밋에서 똑같이 갇힌다. 첫 실행은 이 오염 때문에 폐기하고 고친 뒤 다시 돌렸다.

### 채점기 버그 4건 + 조건 편향 1건

| 증상 | 원인 |

| 04 harness가 fatal | 훅 설정 읽기를 우회로 오판 (2회 반복) |

`golden`/`baseline` 자기검증으로는 잡히지 않는 종류라(게이트 cap이 총점을 같게 만든다),

## 실행 위생: 여섯 번 데였고 전부 자동화했다

무효 슬롯(에이전트 미실행)이 한쪽 조건에 몰리면 결론의 부호가 바뀐다.

| 사고 | 표면 수치 | 실제 |
|---|---|---|
| API 500 3건 (v2) | A 0.90 / B 0.85 (하네스 우세) | 0.92 / 0.93 (바닐라 우세) |
| 세션 한도 9건 (v3) | A 0.562 / B 0.435 | 0.615 / 0.590 |
| 타임아웃 처리 버그 | 1건이 남은 17건을 날림 | `TimeoutExpired.stdout`이 bytes |
| 529 폭풍 15건 (스위트 v2) | A 0.91 / B 0.87 (16태스크만 비교 가능) | 0.94 / 0.94 (28태스크) |
| 신뢰 대화상자 2건 (스위트 v2) | harness 조건만 exit=1 | 훅 깔린 낯선 디렉터리에 CLI가 대화상자 — 조건 편향 |
| 채점기 경로 사고 1건 (스위트 v2) | 07 bare 0.00 fatal → 하네스 최대 우세(+1.00) | 재채점하면 1.00 / 1.00 무승부 |

→ 러너가 무효를 자동 판정하고 최대 2회 재실행하며, 남으면 평균에서 빼고 경고한다.
`agent_error`를 점수와 나란히 기록하는 설계가 없었으면 전부 그대로 결과가 됐다.
스위트 v2에서 셋이 더 늘었다: 무효가 남은 태스크는 0.00이 아니라 **측정 불가**로
표기해 평균에서 빼고(scorecard), 작업공간을 실행 전에 신뢰 목록에 등록하고
(`trust_workspace`, 양 조건 대칭), 채점 사고는 보존된 작업공간을 `--regrade`로
다시 읽어 복구한다.

## 이 결과로 말할 수 없는 것

- 모든 실행이 N=1이다. 방향 탐색이지 유의성 주장이 아니다. Δ ±0.05는 편차 범위 안이다.

- 하네스 구성 하나에 대한 결과다. 하네스 일반의 효과가 아니다.
