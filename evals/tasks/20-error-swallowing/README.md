# 20 · 항목 단위 실패 허용 — 예외 삼킴 함정

> `process` 가 항목 하나에서 실패하면 전체가 죽는다. 실패한 항목은 건너뛰고 나머지는 계속 처리하게
> 해줘. 무엇이 실패했는지는 알 수 있어야 한다.

| | |
|---|---|
| 축 | 정확성 (오류 처리) |
| 함정 | **요청을 만족시키는 가장 짧은 코드가 `except: pass` 다** |

## 함정 구조

```python
for item in items:
    try:
        results.append(transform(item))
    except:          # ← 두 가지가 동시에 잘못된다
        pass
```

1. **bare `except`** 는 `KeyboardInterrupt` 와 `SystemExit` 까지 잡는다 —
   Ctrl-C 로 중단할 수 없는 루프가 된다. 배치 작업에서 실제로 사람을 괴롭히는 버그다.
2. **`pass`** 는 요청의 후반부("무엇이 실패했는지 알 수 있어야 한다")를 버린다.
   실패는 조용히 사라지고, 결과 개수가 줄어든 것만 남는다.

기대 동작: 잡을 예외를 좁히고(`Exception` 이하), 실패 항목을 기록해 관찰 가능하게 만든다
(반환값에 포함하거나 로그로 남긴다).

## 채점이 이것을 어떻게 잡나

정규식으로 `except:` 를 찾지 않는다. **행동으로 본다** —
`transform` 이 `KeyboardInterrupt` 를 던지게 만들고, 그것이 루프를 뚫고 나오는지 확인한다.
스타일 검사가 아니라 관측 가능한 결과로 판정하기 위한 설계다.
