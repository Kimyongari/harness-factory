# 04 · 이중 장부 대사 (data-analytics · hard)

**질의**: 부호 체계가 다른 은행 명세(음수=출금)와 내부 장부(양수+debit/credit)를 대사해
불일치 전부를 `discrepancies.csv`(헤더·정렬·빈 칸 규칙 고정)로 내라.

**심은 불일치 12건 + 함정** (설계 원칙 ① 산출물 계약 + ② 검증 루프):

1. **한쪽에만 있는 거래** — 은행에만 4건(missing_in_books), 장부에만 3건(missing_in_bank).
2. **금액 불일치 5건, 그중 2건은 정확히 1센트 차이**(T-0022: 4137.29 vs 4137.30,
   T-0049: 892.13 vs 892.12) — `abs(a-b) < 0.01` 류의 허용오차 비교, 또는 float 절단으로
   센트가 뭉개지는 파이프라인이 이 2건을 놓친다. 재현율(0.25)의 관문.
3. **날짜가 하루 밀린 동일 거래 3건**(T-0010·T-0028·T-0053) — 규칙상 같은 거래(±1일)라
   불일치가 아니다. (txn_id, date) 완전 일치로 조인하면 이 3건이 과잉 보고로 나타난다.
   정밀도(0.25)의 관문.
4. **센트 환산 float 함정** — 출력 대상 금액 중 4건(19.99·1074.10·1310.11·64.07)은
   `int(x*100)` 절단이 1센트 틀리는 값이다. 불일치를 다 찾아도 금액 컬럼(0.2)에서 떨어진다.
5. **파일 순서 ≠ 매칭 순서** — 두 파일 모두 날짜순 정렬이라 행 위치로는 못 맞춘다.
   txn_id 조인이 강제된다.

**채점 방식**: 기대 12건은 grade.py 에 하드코딩(출처: heldout/gen_fixtures.py 의 역할표 —
파일 재파싱이 아니라 심은 모델에서 직접 생성). gate 는 파일 존재+헤더 완전 일치, 이후
재현율(0.25)·정밀도(0.25)·금액 컬럼 완전 일치(0.2)·정렬/형식(0.15)을 분리 판정한다 —
"놓친 실행" 과 "과잉 보고한 실행" 이 다른 항목에서 떨어져 실패 모드가 점수에 남는다.

**왜 이 태스크인가**: 규칙은 전부 프롬프트에 있다(데이터 사전·±1일·부호 정규화·형식).
어려움은 지식이 아니라 실행 품질이다 — 12건을 하나도 빠뜨리지 않고, 3건을 끼워 넣지 않고,
센트를 1도 안 틀리는 전수 대조. 대충 훑어 "큰 것 몇 개" 만 보고하는 실행과 검산까지 도는
실행이 네 항목에서 따로따로 갈린다 (Harness-Bench: 계약/형식 위반 36.4% 겨냥).
