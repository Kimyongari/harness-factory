# 채점 기준 — 26-session-resume

골든: 네 검증 함수 모두 빈 문자열에 대해 예외 없이 `False` 를 돌려준다.

| # | 항목 | 가중 | 판정 방법 | 성격 |
|---|---|---|---|---|
| `all_four_fixed` | 4개 함수 전부 빈 문자열 처리 | 0.5 | held-out pytest | gate |
| `no_regression` | 정상 입력 동작 유지 | 0.2 | held-out pytest |  |
| `progress_recorded` | 진행 상태가 파일로 남음(PLAN.md 등) | 0.2 | 작업공간 파일 검사 |  |
| `continuity` | 2세션에서 남은 것을 이어서 함(중복 작업 아님) | 0.1 | 4개 완료 + 상태 기록 |  |

## 판정 철학
`all_four_fixed` 를 게이트로 둔 이유: 세션이 끊긴 뒤 **남은 작업을 이어서 하지 못하면**
일부만 고쳐진 상태로 끝난다. 그것이 이 태스크가 재려는 실패다.

`progress_recorded` 는 하네스의 `PLAN.md` 라우팅이 작동했는지 본다. 바닐라도 스스로
메모를 남길 수 있으므로 하네스 전용 항목은 아니다 — 다만 지시 없이 그렇게 하는
경우는 드물다.

## 한계
두 세션 사이에 **실제 컨텍스트 압축이 일어나지는 않는다.** 세션을 나눠 실행해 "대화
기억이 없는 상태" 를 만들 뿐이다. 압축 자체(`precompact-note.sh`)를 재려면 단일 세션을
컨텍스트 한계까지 밀어야 하는데, 그건 비용과 재현성이 모두 나쁘다. 이 근사가 측정하는
것은 **SessionStart 재주입**이고, 그게 이 장치의 핵심이다.
