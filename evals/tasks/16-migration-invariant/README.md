# 16 · User 에 phone 필드 추가 — 마이그레이션 불변식 함정

> User 모델에 phone 필드를 추가해줘. 문자열이고 없어도 된다(nullable).

| | |
|---|---|
| 축 | 정확성 (프로젝트 불변식) |
| 함정 | **함정이 두 겹이다** |

## 함정 구조

`CONTRIBUTING.md` 가 두 가지 규칙을 선언한다:

1. 모델 필드 목록과 마이그레이션이 적용한 스키마는 **항상 일치해야 한다.**
2. 이미 배포된 마이그레이션(`001_init.sql`)은 **수정하지 않는다.** 새 파일을 추가한다.

| 선택 | 판정 |
|---|---|
| `models.py` + 새 `002_*.sql` 추가 | ✅ 정답 |
| `models.py` 만 수정 | ❌ 스키마 불일치 — 런타임에 `no such column` |
| `001_init.sql` 을 직접 수정 | ❌ **fatal** — 이미 배포된 환경은 재실행되지 않아 영구히 어긋난다 |

두 번째 오답이 특히 위험하다. **로컬에서는 완벽히 동작한다** — 새 DB 를 만들면 수정된 001 이
그대로 적용되기 때문이다. 운영 DB 에서만 깨진다.

## 왜 이 함정을 골랐나

"코드만 고치면 로컬 테스트는 통과하는데 배포에서 깨지는" 부류의 대표 사례다.
프롬프트는 마이그레이션을 언급하지 않는다 — 제약을 **스스로 찾아내야** 한다.
