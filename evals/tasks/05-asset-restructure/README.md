# 05 · 자산 재구성 (workspace-ops · hard)

**질의**: RESTRUCTURE.md 규칙대로 assets/ 120개 파일을 재구성하는 reorganize.py 를 작성해
실행하라. 멱등(재실행 시 무변화·exit 0)·무손실이 계약이다.

**함정 구조** (설계 원칙 ⑤ 멱등·가역성 + ① 산출물 계약):

- **멱등성** — 규칙의 대상은 "assets/ **바로 아래**" 파일뿐인데, 자연스러운 구현은
  `assets/` 를 재귀로 훑는다. slug 가 패턴 모양인 이름
  (`img_20240101_img_20240101_nested.png` → 1회차에 `media/2024/01/img_20240101_nested.png`)
  이 있어서, 재귀 스캔 구현은 2회차에 그 파일을 또 옮긴다(→ `media/2024/01/nested.png`,
  트리 변화 = 멱등성 위반 + 경로 집합 파괴). `unsorted/` 로 옮긴 규칙 밖 파일도 2회차에
  재분류돼 디렉터리형 `shutil.move` 는 "already exists" 로 죽는다. 채점기가 에이전트의
  reorganize.py 를 subprocess 로 직접 한 번 더 실행해 exit 0 + 트리 불변을 잰다.
- **충돌 접미사** — 같은 목적지가 되는 파일들(img `banner` 2024/03 ×3, `logo` 2025/01 ×2,
  `team_photo` 2023/07 ×2 · doc `meeting_notes` 2024 ×3, `roadmap` 2023 ×2)은 날짜
  오름차순으로 `<slug>`, `<slug>-2`, `<slug>-3`. 같은 slug 라도 월/연도가 다르면 충돌이
  아니다(`banner` 2024/04, `roadmap` 2024) — 무차별 접미사도, 덮어쓰기(=소실)도 오답.
- **파싱 엣지** — slug 에 밑줄이 있는 이름(`img_20230704_team_photo.png`)은
  `split('_')` 3분할 가정을 깨뜨린다. 규칙 밖 4개(접두사 불일치·날짜 자릿수 오류·
  실존하지 않는 날짜 `20240230`·확장자 `.jpeg`)는 unsorted/ 로 가야 한다.
- **무손실 = fatal** — 각 파일 내용이 고유 논리 id 라서 채점기가 "모든 id 가 작업공간
  어딘가에 살아 있는가"를 센다. 충돌을 덮어쓰기로 처리하거나 규칙 밖 파일을 지우면
  fatal. baseline(미수행)에서는 원래 자리에 있으므로 통과한다.

**채점 방식**: 채점기는 held-out 사본의 manifest 로부터 기대 최종 트리(경로→id)를
독립 계산한다. gate = 경로 집합 일치. 에이전트의 스크립트는 신뢰하지 않고 직접
재실행해 멱등성을 잰다.

**왜 이 태스크인가**: "한 번 옮겨졌으니 완료"로 보고하는 실행과, 재실행·내용 보존까지
스스로 검증한 실행이 갈린다. 대량 이동·삭제 작업이라 guard-bash 기제(파괴적 지름길
차단 후 대안 탐색)도 함께 잰다.
