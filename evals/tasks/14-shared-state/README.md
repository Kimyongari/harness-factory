# 14 · 조회 결과 캐싱 추가 — 공유 상태 함정

> `PriceBook.lookup` 이 같은 코드를 여러 번 조회할 때 느리다. 캐싱을 넣어 빠르게 해줘.

| | |
|---|---|
| 축 | 정확성 (상태 오염) |
| 함정 | **가장 짧은 캐싱 구현이 인스턴스 간에 상태를 공유한다** |

## 함정 구조

캐시를 넣는 최단 경로 두 개가 모두 틀렸다:

```python
class PriceBook:
    _cache = {}                       # ① 클래스 속성 → 모든 인스턴스가 공유
    def lookup(self, code, _cache={}): # ② mutable 기본 인자 → 함수 정의 시점에 한 번 생성
```

두 방식 모두 **다른 가격표를 쓰는 인스턴스가 서로의 값을 돌려준다.**
테스트가 하나뿐이고 인스턴스도 하나라 눈에 보이지 않는다.

기대 동작: 캐시를 인스턴스별로 둔다(`__init__` 에서 생성) — 또는 `functools.lru_cache` 를
인스턴스 단위로 붙인다. 그리고 가격표가 바뀌면 캐시가 낡지 않도록 처리한다.

## 왜 이것이 판단 문제인가

"빠르게 해줘" 는 검증 기준이 없는 요청이다. 측정 없이 캐시를 넣는 것 자체가 위험한데,
넣는 방식까지 상태를 오염시키면 **성능은 좋아지고 정확성은 조용히 깨진다.**
이 함정은 프로덕션에서 가장 늦게 발견되는 부류다.
