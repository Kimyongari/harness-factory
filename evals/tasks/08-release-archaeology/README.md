# 08 · 릴리스 고고학 (knowledge-evidence · hard)

**질의**: releases/v0.1~v0.9 아카이브를 뒤져 questions.md 의 질문 4개(반환 타입 변경
시점·버그 도입/수정 버전·문서-코드 불일치 버전·상수 변화 이력)에 답하고, 답마다
근거 코드 줄(file:line)을 answers.json 에 인용하라. git 없는 오프라인 고고학이다.

**정답과 함정 구조** (설계 원칙 ③ 근거 강제):

- **q1 = v0.5** — `check` 가 bool → dict(`{"allowed", "remaining"}`)로 바뀐다.
  CHANGES.md 에도 적혀 있지만 증거는 코드 줄이어야 한다.
- **q2 = 도입 v0.3 / 수정 v0.8** — v0.3 이 `remaining` 의 `max(0, …)` 클램프를
  조용히 떨어뜨린다(그 버전의 CHANGES 항목은 reset 추가만 언급 — 누락이지 거짓은
  아니다). check 가 증가 후 비교라 거부된 요청도 세어져 음수가 실제로 나온다.
  v0.8("카운터 경계 처리 수정")이 클램프를 복원한다. 문서만 읽으면 도입 버전을
  알 수 없다 — 코드 diff 만이 근거다.
- **q3 = v0.6** — CHANGES 는 "내부 정리, 동작 변화 없음"이라지만 실제로는
  `_normalize`(strip+lower)가 추가돼 키가 대소문자 무시로 바뀐다. 변수명·docstring
  정돈이 진짜로 섞여 있어 대충 보면 정리로만 보인다. **문서와 코드의 불일치가 핵심
  함정**이다.
- **q4 = [(v0.1, 60), (v0.4, 30), (v0.7, 45)]** — WINDOW_SECONDS 의 변화 버전만,
  오름차순, 항목별 증거 대응.

**채점 방식**: 답 정확 0.6(질문당 배분) + evidence 0.25 + 스키마(gate)·형식 0.15.
evidence 는 07 과 같은 방식 — 채점기가 질문별 허용 증거 목록(파일+정규식)을 갖고
인용된 file:line 을 pristine project/ 에서 열어 ±1줄 안에서 대조한다. 존재하지 않는
파일·줄 인용이 하나라도 있으면 evidence 전 항목 0. 답이 틀리면 그 답의 증거도
불인정.

**왜 이 태스크인가**: Harness-Bench "근거 부족" 실패 모드의 조사(research) 변형이다.
CHANGES.md 는 q1·q4 를 거의 공짜로 주지만 q2 도입 버전과 q3 는 9개 버전을 실제로
대조해야만 나온다 — 요약 문서를 신뢰하는 실행과 원본(코드)을 검증하는 실행이 갈린다.

**함정이 아닌 것**: 코드 안에 버그 표식·주석 힌트 없음. v0.6 의 거짓 요약이 유일한
문서-코드 모순이고(q3 정답 유일성), 나머지 CHANGES 항목은 전부 사실이다.
