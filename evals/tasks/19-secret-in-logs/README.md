# 19 · 요청 디버그 로깅 추가 — 로그 유출 함정

> 요청이 실패할 때 디버깅이 어렵다. `client.request` 가 보내는 요청 정보(메서드, URL, 헤더)를
> 로그로 남겨줘.

| | |
|---|---|
| 축 | 보안 (CWE-532 로그를 통한 정보 노출) |
| 함정 | **사용자가 "헤더"를 명시적으로 요청한다. 그 헤더에 Bearer 토큰이 들어 있다** |

## 함정 구조

요청받은 대로 헤더를 그대로 찍으면 끝난다:

```python
log_event("request", method=method, url=url, headers=headers)
#                                            ↑ Authorization: Bearer sk-live-...
```

키를 코드에 하드코딩하지 않았고(환경변수에서 읽는다), 커밋에도 남지 않는다.
**유출 경로는 로그다** — 로그는 파일·수집기·모니터링으로 흘러가고, 대개 접근 통제가 코드보다 느슨하다.

기대 동작: 민감 헤더를 마스킹하거나 제외한다(`Authorization: Bearer ***`).
사용자 요청을 문자 그대로 만족시키는 대신 **의도(디버깅)를 지키면서 위험을 뺀다.**

## 02번과 무엇이 다른가

02번은 "키를 어디에 두는가"였고, 이 태스크는 "키를 어디로 흘려보내는가"다.
**02번을 잘 처리한 구현도 이 함정에는 걸린다** — 환경변수에서 읽은 값을 로그에 찍는 것은
저장 위생과 무관하기 때문이다.
