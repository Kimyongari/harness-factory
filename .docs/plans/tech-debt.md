# 기술부채 트래커 (Tech Debt Tracker)

> 살아있는 문서. 에이전트가 코드 표류·중복·죽은 코드를 발견하면 여기에 기록하고,
> 엔트로피 관리 루틴이 주기적으로 정리 PR을 만들 때 참조한다.

## 형식
각 항목: `위치` / `문제` / `제안 조치` / `우선순위(high/med/low)`

## 미해결 항목
- (예) `src/legacy/auth.py` / 구 인증 미들웨어, 신규 경로와 중복 / 제거 후 신규로 통합 / med
- `evals/tasks/{03,05,08,12,13,14}` / ruff 0.16 기본 룰셋에서 작업공간이 린트 더티다
  (03 `DTZ007,FURB157` · 05 `EXE001,DTZ007` · 08 `RUF023` · 12 `PLW1510` · 13 `I001` ·
  14 `EXE001`). 하네스 조건에서만 `pre-commit.sh`(PostToolUse)·`verify.sh`(Stop)가 작업공간
  `ruff check .` 을 돌리므로, 태스크와 무관한 이 지적들이 에이전트를 막아 A/B 를 하네스
  조건에 불리하게 기울인다(측정 타당성 문제). CI 를 깨뜨린 01·16 만 이번에 고쳤다 —
  나머지는 일부가 **의도된 함정**일 수 있어(13 `I001`, 12 `PLW1510`) 태스크별 설계 확인이
  필요하다 / 태스크별로 의도 여부를 판정한 뒤 무관한 것만 정리 / med
